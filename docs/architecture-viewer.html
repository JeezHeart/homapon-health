FIGURE 7Connected mode shown; standalone demo uses fictional local records

System Architecture of the Proposed System

Health workers use the website to keep child records, plan vaccination visits, prepare reports, and request text reminders. BHW means Barangay Health Worker.

How to read it. Staff use the website to work with saved records. The connected system checks staff access before accepting changes. Record Review runs inside the website and checks patterns in recorded vaccine dates. It does not diagnose health, confirm an error, change records, or send texts. The diagram shows connected mode; the standalone demo uses fictional local records. Demo texts do not reach a phone; real sending needs a separately approved setup.

FIGURE 8Based on the paper; health-center confirmation still needed

Process Flow of the Manual Transaction

This shows the paper-based visit described in the manuscript. A health professional decides whether a child should receive a vaccine.

How to read it. Read from top to bottom. If the vaccine is given, staff record what was given and when. If it is postponed, staff explain the next step. They tell the guardian when to return. Follow-up is needed for a missed expected visit or another concern; an unfinished vaccine series does not automatically mean a missed visit. The health center still needs to confirm the exact steps.

FIGURE 9Example workflow; staff choose which action is needed

Process Flow of the Proposed System

The system helps staff record vaccinations and plan visits. The regular clinic day is Wednesday. Staff choose another date when needed and write the reason.

How to read it. This is an example of a visit and its follow-up, not a required order for every screen. Staff record a vaccine after it is given. The system compares appointment dates with saved doses. A past appointment date without a matching dose record needs follow-up; it does not prove that the child was absent. Optional Record Review needs all nine selected vaccine dates before it can run. Staff check the logged reminder outcome; a demo result does not confirm delivery. Reports and printing are also available without sending a text.

FIGURE 10Staff functions; SMS is simulated; live recipients require approved setup

Use Case Diagram

Health workers and midwives share the main functions, including experimental Record Review. Only midwives can delete child and vaccination records. Guardians do not sign in.

How to read it. Lines connect people and services to the functions they use. Empty triangle arrows show that BHWs and midwives are both health-center staff. Both roles can view reports and review date patterns. Deleting child and vaccination records is restricted to midwives; appointment deletion has no matching midwife-only check in the server code. Dashed links to the text service and guardian apply only to an approved live setup. Guardians do not sign in, and demo texts do not reach phones.

FIGURE 11Simplified record model; references and calculated fields are identified

Class Diagram

Each child record connects to vaccination records, appointments, and text-message records. Guardian details are included in the child record.

How to read it. This is a simplified record class diagram. Each box names a record type and its information. The label 1 to 0 or more means one child may have no related entries yet, or many; each related entry belongs to one child. No invented operations or diagnosis fields are added. The vaccine list explains vaccine names and doses; it is a reference list kept with the website. Dashed lines show a reference or supporting action. The staff activity record stores the staff name, action, record type, identifier, and time when logging succeeds. It does not store a full before-and-after copy. No medical diagnosis or AI risk score is stored in these records.

FIGURE 12Connected system: success path; entry or save failures stop it

Steps in saving a vaccination record

The staff member enters a vaccination that was already given. The system checks access and the entry before saving it.

How to read it. Read the arrows from top to bottom. Each column is a person or part of the system. The system checks the staff account, the child record, and whether the same dose is already recorded. It then saves the entry and shows success. If a check or save fails, it shows a problem. The system also tries to note who made the change; failure to save that extra note does not undo the vaccination record.

FIGURE 13Simplified program groups; arrows show which part uses another

Package Diagram

The program has groups for screens, staff actions, entry checks, and saved records. Experimental Record Review runs in the website; model training is a separate preparation step.

How to read it. The screen collects the staff member's entry. Other parts check it and send it to the saved records. The vaccine guide and date rules help the screens show useful information. Record rules describe which details belong in each record and which entries are allowed. These are parts of the existing program, not separate products that the health center must buy.

FIGURE 14Planned setup; not proof that it is already in use

Deployment Diagram

The planned setup connects a health-center browser to website hosting, backend processing, and managed sign-in and records. Live reminders require a separate approved setup.

How to read it. The health-center computer opens the website. Online services check staff access and handle records. A text service can pass reminders to a guardian's phone, and a local printer can print child records. Render is the selected planned host for the main program; deployment is deferred. Experimental date review runs on the staff device inside the website. The diagram is a plan; it does not prove that the system is already running for the health center or that a message reached a phone.

WHAT THE HEALTH CENTER NEEDSPlanning guide; check the actual equipment first

Hardware and Software Requirements of the Proposed System

Before using the system at the health center, check the computer, internet connection, printer, staff accounts, and online services. The list below is a planning guide, not a promise that every device will work.

AreaBasis for this system
Health-center computerA desktop or laptop with an internet browser, keyboard, and a screen staff can read comfortably. Test the actual device.
Internet connectionNeeded to sign in, use saved records, and send approved text reminders. This diagram collection can be read offline.
PrinterOptional for printed child records. Staff can also save a PDF instead of printing.
Website and record servicesOnline services keep the website available, check staff access, and store records. Render is selected for the main program, but deployment is deferred.
Text-message serviceRequires an approved account and sending setup. Staff must check unclear sending results before trying again.
Experimental Record ReviewRuns inside the website using a saved model and nine recorded vaccine dates. It suggests date patterns for staff to check; it does not diagnose health. Training the model is separate from daily use.
